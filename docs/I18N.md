# INTERNATIONALISATION (i18n) — ALMERÍAGA

Cinq variantes sont proposées dans le sélecteur de drapeaux du header :

| Code | Langue | Sens de lecture | Fichier |
| --- | --- | --- | --- |
| `fr` | Français (référence) | LTR | `lib/i18n/dictionaries/fr.ts` |
| `ar` | Arabe | RTL | `lib/i18n/dictionaries/ar.ts` |
| `es` | Espagnol | LTR | `lib/i18n/dictionaries/es.ts` |
| `en` | Anglais | LTR | `lib/i18n/dictionaries/en.ts` |
| `dz` | Algérie — hybride 90 % FR / 10 % AR | LTR + îlots RTL | `lib/i18n/dictionaries/dz.ts` |

## Fonctionnement

1. Le visiteur choisit une langue dans `components/i18n/LanguageSwitcher.tsx`.
2. Le composant pose le cookie `almeriaga_locale` (1 an, `SameSite=Lax`, `Secure` en HTTPS)
   puis appelle `router.refresh()` : **aucun rechargement complet, le défilement est conservé**.
3. `lib/i18n/server.ts` lit le cookie dans le layout et rend le HTML **déjà traduit**
   (`<html lang="ar" dir="rtl">`). Bénéfices : SEO correct, pas de clignotement de langue.
4. Les composants serveur appellent `getLocaleContext()` ; les composants client
   (Navbar, formulaire, sélecteur, catalogue, simulateur) lisent `useI18n()`.
   Le dictionnaire est transmis au `I18nProvider` du layout (données sérialisables, aucune
   fonction dans les dictionnaires).

> Conséquence assumée : lire le cookie dans le layout rend les pages **rendues à la demande**
> (ƒ dans le rapport `next build`) au lieu d'être statiques. C'est le prix d'un HTML déjà
> traduit, sans clignotement ni double rendu client. Le site reste léger (≈ 87 kB de JS partagé).

## Ajouter ou modifier un texte

- **Une seule source de vérité** : `lib/i18n/dictionaries/fr.ts` définit le type `Dictionary`.
- Ajoutez la clé en français, puis dans `ar.ts`, `es.ts` et `en.ts`.
  TypeScript échoue (`satisfies Dictionary`) tant qu'une langue n'est pas à jour.
- Le mode `dz.ts` n'est qu'une **surcharge partielle** de `fr` : n'y mettez que les
  quelques chaînes qui doivent passer en arabe algérien.

```ts
// lib/i18n/dictionaries/fr.ts
hero: { cta: 'Réserver' }
// lib/i18n/dictionaries/dz.ts
hero: { cta: 'Réserver · احجز' }
```

## Mode hybride DZ

`dz.ts` part du français (usage professionnel local) et remplace environ 10 % des chaînes
par de l'arabe algérien : titres et badges de sections, CTA principaux, libellés des champs,
message de remerciement. La mise en page reste **LTR** ; les fragments arabes sont des îlots
bilingues rendus par le navigateur (algorithme bidi), sans casser la grille Figma.
Un test (`tests/i18n.test.ts`) vérifie que la part arabe reste entre 5 % et 25 %.

## RTL et arabe

- `<html dir="rtl">` en arabe ; Tailwind reste inchangé, quelques règles ciblées sont dans
  `app/globals.css` : chevron des `<select>` déplacé à gauche, icônes directionnelles
  miroir (`.icon-directional`), letter-spacing remis à zéro pour l'arabe.
- Pile de polices arabe système (`--font-arabic`), aucun téléchargement (CSP stricte).
- Les noms des 58 wilayas sont traduits en arabe dans `lib/i18n/wilayas.ts`
  (les noms latins restent la référence pour le stockage et Google Sheets).
- Les numéros de téléphone restent en `dir="ltr"` et acceptent les chiffres arabo-indiens
  (`٠٥٥٠…`) grâce à `toAsciiDigits()` dans `lib/validation.ts`.

## Formulaires et API

- Les libellés, aides, consentements, états de chargement et messages de succès viennent du
  dictionnaire (`dict.form`).
- La validation client reçoit `dict.form.errors` ; l'API revalide avec la même table et
  renvoie ses erreurs dans la langue du `locale` envoyé par le formulaire.
- Chaque lead transmet `locale` (+ `requestType`) à Google Sheets ; la colonne `type_demande`
  vaut `Consommateur`, `Revendeur` ou `Liste d'attente`.

## Hors périmètre i18n (volontairement en français)

- Le **corps** de `/mentions-legales` reste en français : c'est la version de référence.
  Un bandeau localisé prévient le visiteur que cette version fait foi (traductions juridiques
  à faire valider par un professionnel avant publication).
- La page `/connexion` est localisée ; le corps de `/mentions-legales` et de `/cadre-legal` reste en français (version de référence) avec un bandeau localisé.

## Vérifier

```bash
npm run typecheck   # clés manquantes dans une langue
npm test            # parité des clés, ratio DZ, wilayas, validation localisée
npm run build
```

Test manuel : ouvrir le site, choisir chaque drapeau, vérifier que l'URL ne change pas,
que le header passe en arabe (RTL) et que le formulaire répond dans la langue active.
